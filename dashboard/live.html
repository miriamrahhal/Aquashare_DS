AquaShare

A distributed system that shares a limited water supply fairly between farms.

The problem

Farms share one reservoir with a daily limit. Each one needs to know its share, use it even when its internet drops, and nobody should be able to take more, cheat, or lose the records if a server crashes.

Our solution

Each morning the operator opens a day and every farm gets a share. Farms water from their own share (escrow) and send signed reports. A ledger kept on 3 servers saves every litre, so the records survive crashes and lies.

How it is built

Distributed systems ideas you will see live

  • Consensus (Raft)3 servers agree on every record; if the leader crashes, another takes over.
  • Works offlineA farm keeps watering from its own share and syncs later.
  • Exactly onceA transfer sent twice is counted only once.
  • Majority readsIf one server lies, the other two outvote it.
  • Mutual TLS + rolesEvery connection shows a certificate; the name decides the rights.
  • Proof of recordsSigned reports and Merkle proofs show a record is real.

How mutual TLS protects every connection

  1. Both sides show a certificate. Normal HTTPS only checks the server. Mutual TLS also checks the client, so every farm, gateway and script must prove who it is.
  2. Both check the signature. A certificate counts only if the AquaShare CA signed it. No certificate, or a fake one: the connection is refused before any request is read.
  3. The channel is encrypted. Nobody on the network can read or change the reports.
  4. The name decides the rights. The gateway reads the name in the certificate: farm-a may only send its own water; only the operator may open a day (otherwise 403).
  5. Inside, the same rule. The 3 ledger servers talk to each other over gRPC with TLS, and each farm also signs its reports with its own key (Ed25519).

This page itself is plain HTTPS: browsers have no certificate, so the dashboard only shows the system and cannot change it.
